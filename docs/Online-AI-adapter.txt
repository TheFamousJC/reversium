Online account adapter preparation

Production state: disabled. No OAuth URLs, provider credentials, token exchange or inference endpoint is shipped. Approval pending; the user reports submitting the OpenAI interest form. Preparation is not proof of access or a working account integration.

web/online-ai.mjs provides the tested connection/request lifecycle, exact packet validation, consent gate, response citation checks, cancellation and stale-result suppression. web/online-ai-config.mjs is disabled and approvedAdapter is null. Never enable using another app's client ID or a user API key.

The report stays network-disabled. It requests actions from the parent app with postMessage; the parent accepts only its own report frame. Tokens never enter the report. Only a reviewed {question,evidence:[{id,text}]} packet is passed to an adapter. ZIP buffers and entire reports are never forwarded. Each send requires fresh explicit approval. Invalid/expired/error results produce no claimed verified answer and no automatic retries. Answers are rendered as text with source links. Citation validation checks references, not semantic truth.

Adapter interface for the approved deployment:
connect({signal}) -> {connected:true} only after provider-approved OAuth authentication and ChatGPT plan-use authorization; never return credentials to the frame.
ask(packet,{signal}) -> {claims:[{text,evidence_ids:[id]}],unknowns:[string]} with bounded content. Use a server/session design confirmed by OpenAI; identity sign-in alone is insufficient. Authentication and rate limit errors must not expose raw provider bodies or secrets. SESSION_EXPIRED forces reconnection.
disconnect() -> revoke/clear the application session, abort requests and remove retained provider credentials according to the approved architecture. The UI clears answers on disconnect and Start again.

Activation checklist after approval: confirm hosted OAuth client, allowed redirect/origins, scopes, token and refresh storage, approved inference transport, supported models, usage accounting and hosting. If backend required, implement secure server session cookies, CSRF/state/nonce/PKCE, issuer/audience/signature validation and authorized origin checks. Keep refresh tokens server-side if that is the approved model. Do not guess CORS support. No endpoint, model or scope is preselected here. Add rate/size limits, timeout, expiry and revoke tests. Explain exactly which service receives selected evidence. Update privacy/Help before activation. Do not enable the public config until live end-to-end verification with a consenting account succeeds. Manual handoff and local analysis remain independent.

Tests: node --test tests/online-ai.test.mjs (fake in-memory adapter only, no network or OpenAI calls).
