About Reversium

Build 0.14.0 · Open Source · 3Sci.com · 2026

Reversium helps you understand an unfamiliar software package before you take responsibility for it. You give it a ZIP, and it examines the files on your computer to produce an organized report. You do not need to understand programming to start exploring the results.

Where does Reversium fit?

Use Reversium as a private first step for handover and maintenance discovery. Its combination of browser-local ZIP analysis, supported feature paths, evidence, unknowns and reviewer actions helps bridge software owners and developers. It complements specialist architecture, quality and security tools; it does not replace their depth. Core analysis needs no model, account or paid service.

What can it help you achieve?

Understand what you have received. See which files, programming languages, frameworks and supporting services are referenced. This helps you ask informed questions when buying software, receiving a contractor’s work or inheriting an older project.

Find where a feature lives. Supported source tracing can connect a screen action to a callback, an API request and a database operation. The map gives a developer a starting point for investigating a bug or planning a change. Every supported connection leads back to evidence, and inferred connections remain candidates.

Prepare a practical handover. Use the report to identify the parts a new developer needs to understand, the services the software may require and the questions that still need answers. The report helps plan setup and maintenance; it does not automatically install or run the software.

Review a new delivery. Keep a JSON baseline and compare another package to identify changes in inspected files and mapped references. Keep an HTML report as a readable record for colleagues.

Ask for an explanation. The optional AI assistant can explain selected findings and suggest checks through your own eligible ChatGPT account. You review the question and evidence before sharing. Local analysis still works without AI, an account or an internet connection.

A simple way to use it

  1. Choose the software ZIP and analyze it locally.
  2. Read Software findings, then explore Architecture and its feature paths.
  3. Open Evidence to check where a finding came from. Read Coverage to understand what was not inspected or established.
  4. Save a report and give a developer a short list of questions to confirm with isolated tests.

What the report cannot promise

Finding a reference in code does not prove it runs successfully. Reversium cannot guarantee the complete purpose of an arbitrary program, identify every feature, certify security, prove production readiness or recover missing passwords, data and services. Binary inspection is limited metadata/reference inspection, not full decompilation. Real installation, permissions, business behavior and reliability need separate tests.

The practical benefit is a better starting point for a handover, maintenance investigation or modernization discussion, with evidence and gaps made visible. Local analysis is free and open source; optional cloud AI follows your provider’s eligibility and usage limits.

Coverage and limitations

  • Python symbols/imports use AST parsing; JavaScript/TypeScript imports and endpoint-host candidates use heuristics.
  • Source languages beyond the supported Python, JS/TS and SQL reference readers are inventoried only. No complete call graph, runtime behavior, vulnerability audit, or business requirements recovery is claimed.
  • Binary inspection is bounded static metadata analysis, not decompilation or behavioral verification. Mach-O and DEX receive header identification only. Malformed binaries retain partial findings.
  • Nested containers receive directory inspection only. Files over 4 MiB or compression limits are inventoried without content inspection. Binary string samples may contain private content; URL hosts omit credentials, paths and queries.
  • Local module links are path candidates, not runtime resolution. Aliases, custom search paths, re-exports and dynamic imports may remain unresolved. Ambiguous matches are not selected.
  • Python decorator routes and ORM base-class names are syntax candidates, not verified framework behavior. Non-Python route and import scans can match comments.
  • Only package.json, requirements.txt and go.mod dependencies are extracted. Other known manifests are identified only. File changes are compared only when both reports contain inspected-content hashes.
  • Python AST traces and selected pg/mysql2 operation traces retain their bounded execution-path approximation. The additional TS/React/Supabase graph records lexical references, including conditional code and callbacks, not proven execution. Regex and JSX text are opaque; JSX expressions/component references are scanned. Supabase clients are recognized through named imports, factories, aliases and annotated parameters; dynamic receivers, object-property clients, re-exports, namespace imports, complex prop/event data flow and runtime middleware effects remain unknown. Selected explicit JSX prop bindings, destructured/object props, immutable callback aliases, React useCallback/returned-hook callbacks and literal React.lazy imports receive candidate links. Multiple component usages are combined as possible bindings, not runtime instances. Computed fetch targets use bounded constant strings/concatenation/templates and per-caller helper arguments with method-aware route candidates; arbitrary expressions, mutable bindings, unknown origins and methods remain unresolved. Literal router mounts and API-path matches are candidates, not verified routing. What Reversium helps you do

Reversium reads a software package and organizes supported source and binary clues into findings, diagrams, evidence and explicit gaps. Use it when receiving a handover, inheriting unfamiliar code, investigating a feature or preparing maintenance. It does not install, run or certify the software.

Choose one useful outcome

For an owner: identify what was delivered and agree on one feature to check. For a developer: find likely entry points, dependencies and source locations. For a maintainer: map possible affected components before changing them. A useful outcome is a short, evidence-backed checklist rather than a claim that the entire platform is understood.

A first session in five steps

1. Open the browser version and choose Start exploring. 2. Choose Understand the software, Prepare a developer handover, or Plan maintenance or modernization. 3. Continue to ZIP, select your source-code package and choose Analyze ZIP locally. 4. Read Review findings, then inspect one Architecture workflow and its Evidence. 5. Read Coverage and Save & next steps; save a report and assign the remaining checks.

Example questions

Where does the save action lead? Which services are referenced? Which files should a new developer read first? What configuration, permissions and sample data still need confirmation? Reversium provides investigation leads; isolated installation and runtime tests answer whether those leads work.

Online and local editions

Online browser edition

Open https://thefamousjc.github.io/reversium/web/ . No installation, account or payment is needed for analysis. The app downloads its self-hosted Python runtime, then reads the selected ZIP in a browser worker on your device. Use a current desktop browser. The first visit downloads about 14 MB of app/runtime assets and can take longer.

Local application

Use the open-source repository https://github.com/TheFamousJC/reversium . Install Python 3.10 or newer, open a terminal in the project and run python -m reversium. Open the local address printed in the terminal; it can use a free port. On Windows, Start-Reversium.ps1 is an alternative launcher. Stop the server with Ctrl+C. The base analyzer has no third-party Python dependency; optional AI has separate requirements.

Main differences

Both editions use the same analysis engine, findings and core diagrams. Online: 32 MiB compressed ZIP limit, five-minute worker stop, browser-memory constraints, no embedded cloud account connection. Local web application: 64 MiB upload limit, local Python process and existing optional ChatGPT account connection. Local command line: report exports and baseline comparison without a web page; archive safety limits still apply.

AI differences

Online AI is a manual handoff: select a provider and evidence, review/edit the exact request, download it, then decide whether to paste and submit it on that provider website. It is not an account connection or embedded chat. Local AI offers an account connection inside Reversium; install requirements-ai.txt if needed, follow its connection wizard and review sharing before each request. Eligibility, network access and provider limits apply. A successful sign-in does not guarantee a successful model response.

Which should I use?

Start online for a quick inspection without installing anything. Use local for larger supported packages, repeatable command-line work, comparison or the existing optional account integration. Use neither as proof that a platform is production-ready. Online remains free to analyze; optional AI services follow the terms and limits of the account you choose.

Selecting a package and handling files

Choose the best input

Prefer the project source-code package with manifests and migrations. An installer or binary-only archive provides fewer clues. Do not include unrelated backups, generated dependencies or large media if they are unnecessary. Keep the original delivery intact and analyze a separate copy when preparing a smaller archive.

What stays on the device

The online app does not upload the ZIP. It holds the file and report in page/worker memory, not app-managed localStorage or IndexedDB. GitHub Pages receives normal app and asset requests, including connection information such as IP address; those requests do not include ZIP contents. No input source is executed. No AI evidence is submitted automatically.

Clearing and saving

Cancel and clear stops the worker and returns to Start. Clear and start again removes the report and selected-file references. Closing the page also releases app references; this is not a secure-memory-erasure guarantee. Browser caches may retain application assets. Downloaded reports and requests remain wherever you save them and can contain private filenames or code-derived details. Share them deliberately.

Limits and rejected archives

Online input is limited to a non-empty ZIP no larger than 32 MiB; the local web application accepts up to 64 MiB. Analyzer bounds include 10,000 files, 256 MiB expanded total and 4 MiB content inspection per file, plus compression, path and graph bounds. Encrypted, damaged, unsafe or oversized archives may be rejected or only partly inspected. Nested containers receive bounded directory inspection, not recursive analysis. Read the actual Coverage output.

The logo and build number identify the report generator. Main tabs stay near the top. Technical inventory numbers remain expanded: files, bytes, binary candidates and findings. These are counts of inspected material, not a completeness, quality or security score.

Evidence

Use the search box to filter findings by file, symbol, value, kind or resolution. A source link from a feature opens Evidence and reveals its row. Locations are file and line references, or byte offsets for binary clues; they are not an in-browser source editor. Traced means a supported static reference was found. Inferred means a candidate relationship needs confirmation. Neither means the program ran successfully.

What to do with unknowns

Record the question, the relevant finding, the person who can resolve it, and a concrete verification step. For example: confirm the API route and database table by running one isolated user journey with test data and appropriate permissions. Missing references can reflect unsupported syntax or missing files, not missing functionality.

Supported source analysis

Python uses AST parsing for supported imports, symbols and selected route/data traces. JavaScript/TypeScript and React use bounded token/reference analysis for selected routes, callbacks, prop bindings and computed API targets. Supabase table, RPC, Auth and storage references and selected SQL migration links produce candidates. Other languages and unsupported patterns may receive inventory-only coverage. Inspect the report rather than assuming a language-wide guarantee.

Binary analysis

Binary inspection is bounded static metadata and reference analysis, not full decompilation or behavioral reconstruction. A binary reader finding a format, target or string does not prove that the executable is safe, valid or runnable. Nested APK/JAR/Office/archive containers are not automatically reconstructed into a complete application.

Readiness is a separate test

Reversium does not install dependencies, start services, connect to production, validate database permissions or test a live user journey. To verify a handover, use an isolated environment, disposable accounts and sample data. Record required runtimes, environment-variable names, migrations, storage, integrations, permissions and successful/failed steps. Never assume a referenced cloud service is configured or paid for.

Handover and change-impact review

Handover tab

Open Handover after analysis. Expand Setup clues to inspect referenced environment variable names, names from .env.example/.env.sample/.env.template, package.json script names and declared runtime constraints. Follow their evidence links. The reader does not retain environment values or script commands; names may occur in comments or optional code and do not prove a requirement. Actual .env files are not read by this reader. Current clue display is capped at 240 groups, with omitted counts.

Reviewer checklist

Assign an owner and status to each action and record a verification reference in Notes. Verified by reviewer is your statement, not automated proof. Do not enter credentials or sensitive values. Save the handover checklist JSON for structured records, or save readable handover notes for a colleague. These files can include private review notes. They are not uploaded, included in AI evidence requests or preserved by ordinary report exports. Clearing/closing loses unsaved annotations. Import/restoration of saved checklists is not yet supported.

Change impact tab

Choose a file to find code nodes assigned to that source file by the supported reader. The view explores upstream and downstream graph directions up to three hops, 120 candidate nodes per direction and 60,000 edge checks per direction. These are investigation candidates, not proven affected components. Starting nodes use explicit source-file metadata rather than cross-file evidence locations. File association does not prove runtime execution. Dynamic and omitted references can hide relationships; inferred edges can overstate them. Use source links and isolated tests before estimating or changing software.

Troubleshooting and a practical handover

Runtime cannot start or analysis is slow

Allow the initial app/runtime download to finish and use a current desktop browser. A network interruption, unsupported browser or device memory limit can prevent analysis. Cancel and retry a smaller source-only package, or use the local application. Online analysis stops after five minutes. Do not repeatedly reload a report you have not saved.

Few findings or an empty workflow

Check that the package includes source files and manifests. Read File inventory to see which files were content-inspected versus inventoried only. Read Limitations for unsupported syntax and unresolved links. Binary-only or incomplete source deliveries cannot establish a full platform map.

An evidence link or download is unclear

A source link selects an Evidence row; it does not fetch a repository file. Downloads normally go to your browser download folder or trigger a save dialog. Check browser download controls if a file is missing. HTML is for reading; JSON is for tools; SVG is the drawn diagram; the AI request is only selected text you reviewed.

AI connection or response fails locally

Check the local assistant wizard, optional dependencies, network connection, account eligibility and provider usage limits. Review the error without posting credentials. Signing in and checking connection do not themselves share the ZIP. Do not assume a successful connection proves inference availability; there is no automatic paid API fallback. Online has no live account connection to repair.

A handover you can act on

Choose one important feature and its expected result. Save the HTML and JSON. Give the developer its workflow/evidence and a list of missing services, configuration and data. Agree on an isolated setup test and record the outcome, date and owner for every gap. Decide what is ready, what is blocked and what must be tested next. Keep the report with the exact delivery it describes.

Glossary

API: a request interface between software components. Callback: a function passed to run when an event occurs. Dependency: another package referenced by the code. Manifest: a file listing project settings or packages. Migration: a script describing a database change. Static analysis: reading files without executing the uploaded program. Evidence: the recorded source location or metadata that supports a finding. Unknown: a claim the available inspection has not established.

FAQ

Who would use Reversium?

A software owner checking a handover, a developer inheriting a project, or a team preparing maintenance or migration. Owners get clearer questions to ask; developers get source locations to investigate.

Will it run the software for me?

No. It inspects the archive without executing its code. Use a separate disposable environment for setup and runtime acceptance.

Does a diagram prove a feature works?

No. It shows supported source references and candidate connections. Conditions, configuration, permissions and external services can change what actually happens.

AI assistant questions

Is local analysis still free?

Yes. Inventory, tracing, diagrams and local reports work without AI, sign-in or an internet connection. Cloud AI depends on your plan, eligibility and usage limits. Reversium does not fall back to separately billed API keys.

Does connecting upload my ZIP?

No. Sign-in shares account authorization information, not your ZIP. Each question sends only its approved preview plus assistant instructions. No automatic whole-report upload, tool execution or background evidence retrieval occurs.

Can I trust the answer?

Answers are AI interpretations, not verified runtime facts. Reversium rejects claims with missing or unselected citation IDs, but a valid citation does not prove the interpretation is correct. Open the linked finding and check the unknowns.

Why can’t I connect?

Check the optional dependency, internet connection, ChatGPT account eligibility and plan permission. Sign-in expires after ten minutes; retry if needed. This integration uses OpenAI’s documented open-source sign-in flow. Its availability may change.

What is saved?

Tokens and answers are held only for the running session. Local host and account-registration identifiers are retained under reports/assistant-host.json and reports/assistant-registration.json so the same account can reconnect. To switch accounts, disconnect and remove the registration file locally before reconnecting. Disconnect removes local account tokens; it does not revoke provider-side consent. Manage app authorization in ChatGPT settings. Saved HTML exports omit the question, preview, selection, account identity and AI answer. Export the local analysis separately.

Can the assistant install or run the uploaded software?

No. It can explain selected findings and suggest checks. It has no command, file-editing or execution tools.
